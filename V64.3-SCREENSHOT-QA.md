# ARKA V64.3 — Screenshot QA Plan

## What was corrected

The supplied screenshot set exposed three concrete visual problems:

1. Protected pages had a large secondary content gutter after the fixed rail.
2. Tenant User used nested rectangular surfaces for the welcome/Guardian area, making the page read as stacked boxes.
3. Product cards and console surfaces were visually too square, while the Super Admin dark header title had insufficient contrast.
4. The compact Guardian visualization needed more vertical room so all six relationship nodes remain visible within its stage.
5. Screenshot capture was coupled to assertions, so a failed assertion could prevent later visual states from being written.

## V64.3 changes

- Explicit fixed-rail/main-column geometry for Tenant User, Tenant Admin and Super Admin.
- Canvas-first Tenant User welcome and Guardian composition.
- Rounded product surfaces with a consistent 20–24px radius.
- Larger compact Guardian stage and stronger node containment.
- Super Admin dark heading contrast correction.
- Light-theme blue/white parity for the same geometry.
- Dedicated screenshot matrix covering:
  - Home desktop
  - Home desktop after-scroll
  - Home mobile
  - Home light desktop
  - Home light mobile
  - Login desktop
  - Login desktop after-scroll
  - Login mobile
  - Login light desktop
  - Login light mobile
  - Tenant User desktop / after-scroll / mobile / light desktop / light mobile
  - Tenant Admin desktop / after-scroll / mobile / light desktop / light mobile
  - Super Admin desktop / after-scroll / mobile / light desktop / light mobile

The matrix writes screenshots independently of later assertions. If a route/authentication step fails, the failure is recorded and the current page is still captured rather than silently skipping all remaining artifacts.

## Local verification

- `node scripts/audit-css.mjs` — PASS: no targeted legacy color hits; no orphan selector fragments detected.
- `node scripts/verify-architecture.mjs` — PASS: no targeted iteration-specific class naming violations.
- Full TypeScript/build verification could not run in this isolated environment because project dependencies are not installed and npm registry access timed out; the global `tsc` therefore reports missing package/type declarations rather than source-level validation.
