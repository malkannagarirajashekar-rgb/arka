# ARKA V64.1 — Screenshot Audit

## Screenshots reviewed

Reviewed the supplied capture set (`arka-screenshots(5).zip`) and the additional screenshot captures surfaced in the conversation, including public Home light/dark sections and authenticated Tenant User, Tenant Admin, and Super Admin views.

## Findings turned into code changes

### 1. Tenant User desktop geometry
The Tenant User capture showed the fixed sidebar ending around the left quarter of the viewport while the main workspace began substantially farther right. The cause was the accumulated fixed-rail rules combined with the original flex layout. V64.1 makes the non-enhanced Tenant User shell use one explicit coordinate system: fixed 248px rail + main width `calc(100% - 248px)` + zero competing flex offset. Header content is left-anchored and the workspace content fills the available main column.

### 2. Tenant User / Tenant Admin / Super Admin palette leakage
The captures showed residual olive/green/warm surfaces, especially in Guardian/Temple cards, Tenant Admin hero/context areas, and Super Admin dark cards. V64.1 applies a final blue-only dark contract to the active protected surfaces and embedded Guardian visualization.

### 3. Light-theme continuity
The public Context, Guardian Gate, and Contact captures showed dark-blue rectangular islands against the pale page. V64.1 makes those sections use the same pale page family. Protected light shells use the same blue-white surface family, with white cards where a card is semantically useful.

### 4. Sign-out and action controls
The captures showed dark/gradient treatment on sign-out controls and gradient fills on action buttons. V64.1 makes action buttons solid ARKA blue and sign-out/theme controls transparent/embedded. Decorative gradients remain available for non-interactive visuals.

### 5. Public Context node containment
The Context capture showed the `NOW` relationship label touching/clipping at the upper visualization boundary. V64.1 moves the top relationship node inward and adds Playwright containment checks for every Context node.

## QA changes

The previous tests already checked accessibility, routes, runtime errors, theme controls, and some light-mode contracts. V64.1 adds tests that specifically target what a user can see:

- light public surface continuity;
- dark public green/olive leakage;
- desktop rail/main geometry for every authenticated role;
- dark protected green/olive leakage;
- solid action-control fills;
- Context-node containment.
